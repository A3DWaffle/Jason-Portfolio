Quarter Quest Arcade

A responsive catalog for six fictional arcade games, built to connect playful 1990s art direction with a clear MVC application structure and useful browser interactions.

What I built

More than a themed image

The project is a multi-page MVC application. Its catalog data drives Razor views, while JavaScript adds fast client-side interaction without requiring user accounts or a database.

Search + sorting

Filter games by title or genre, then sort by title, year, rating, or vote count.

Quick View

Open any game in a focused modal without losing the catalog context.

Detail routes

Each title has a dedicated controller-backed details page with a real not-found path.

Favorites

Heart controls persist selected games in browser storage between visits.

Star ratings

Interactive ratings update averages and vote counts while preserving the original seed data.

Hall of Fame

A ranked view orders the catalog by average rating, then uses vote count as a tiebreaker.

Models/Game.cs
public class Game
{
    public int Id { get; set; }
    public string Title { get; set; } = string.Empty;
    public string Genre { get; set; } = string.Empty;
    public int Year { get; set; }
    public string Description { get; set; } = string.Empty;
    public string ImageName { get; set; } = string.Empty;
    public int[] Ratings { get; set; } = Array.Empty<int>();

    public int VoteCount => Ratings?.Length ?? 0;

    public double AverageRating =>
        VoteCount == 0 ? 0 : Ratings.Average();

    public string VoteLabel =>
        VoteCount == 1 ? "vote" : "votes";
}

01 · Data model

One dependable shape for every game

The model keeps titles, artwork, descriptions, and ratings together. Calculated properties prevent rating logic from being repeated throughout the views.

  • Default values avoid unexpected null strings.
  • VoteCount and AverageRating always reflect the rating array.
  • VoteLabel keeps display grammar out of the page markup.
Interview takeaway: I used the model to centralize both the game data and the rules derived from that data.
Controllers/GamesController.cs
public IActionResult Details(int id)
{
    var game = games.FirstOrDefault(g => g.Id == id);

    if (game == null)
    {
        return NotFound();
    }

    return View(game);
}

public IActionResult HallOfFame()
{
    var rankedGames = games
        .OrderByDescending(g => g.AverageRating)
        .ThenByDescending(g => g.VoteCount)
        .ToList();

    return View(rankedGames);
}

02 · Request handling

Routes return the right view and data

The controller finds an individual game from its route ID and returns a real 404 response when no match exists. A separate action creates the Hall of Fame ranking.

  • Route parameters connect URLs to individual records.
  • Missing games are handled explicitly.
  • LINQ sorts first by rating and then by vote count.
Interview takeaway: I kept request handling in the controller instead of mixing it into the page template.

03 · Server rendering

The catalog grows from data, not copied cards

Razor loops over the model to generate consistent cards. Adding another game to the controller automatically gives it the same layout and details link.

  • Model values are rendered into semantic page content.
  • Tag Helpers generate the details-page route.
  • Data attributes expose values needed by JavaScript.
Interview takeaway: The view stays reusable because presentation is generated from structured data instead of duplicated HTML.
wwwroot/js/site.js
function filterGames() {
    const search = document
        .getElementById('gameSearch')
        .value.toLowerCase();

    const cards = document.querySelectorAll('.game-card');

    cards.forEach(card => {
        const title = card.dataset.title.toLowerCase();
        const genre = card.dataset.genre.toLowerCase();
        const matches = title.includes(search)
            || genre.includes(search);

        card.style.display = matches ? '' : 'none';
    });
}

function saveFavoriteIds(ids) {
    localStorage.setItem(

    );
}

04 · Browser interaction

Useful behavior without page reloads

JavaScript reads the data attributes created by Razor to filter cards immediately. Favorites use local storage so choices remain available on that browser.

  • Search matches both game titles and genres.
  • The server-rendered cards remain the source of truth.
  • Local storage adds persistence without accounts or a database.
Interview takeaway: I used client-side code for fast interaction while keeping the core content server-rendered.
